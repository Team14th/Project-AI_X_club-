智能工具柜项目开发记录（最终版）

一、项目背景与个人职责说明  

本项目为智能工具柜物联网系统开发项目，主要功能包括：  
工人通过人脸识别验证身份后取用工具，系统自动控制电子锁开启，并对取用时间、归还时间、取用人员身份及工具数量等信息进行记录，数据上传至云端后由前端进行实时展示与可视化。

项目采用前后端分离架构，本人在项目中主要负责以下工作：  
1. Unity 前端平台的搭建与开发  
2. 前端与后端（WebSocket / HTTP API）的通信连接  
3. 前端实时数据接收与 UI 同步更新逻辑设计  
4. 协助完成前后端联调及后端部署问题排查  
5. 参与 Git 版本管理规范的制定与实践  

二、前端技术选型与总体设计思路  

前端开发平台选择 Unity，主要基于以下考虑：  
 Unity 具备较强的 UI 表现能力，适合实时数据展示  
 可直接导出 Windows 平台 exe 文件，便于项目演示  
 方便后期扩展动画效果或交互逻辑  

在项目模板选择上，采用 Unity 2D 项目模板，前端重点放在信息面板、状态提示和数据可视化展示，不涉及复杂三维建模。

前后端通信方式采用：  
 WebSocket：用于实时接收工具取用与归还数据  
 HTTP API：用于历史数据查询（非实时场景)  

数据交互统一采用 JSON 格式，便于解析和后续扩展。

三、前端开发与环境搭建过程记录  

1. Unity 项目初始化  

完成 Unity 项目创建，并建立基础目录结构，包括 Scripts、Network、UI 等文件夹，为后续功能模块划分提供基础。

2. Git 管理与 .gitignore 配置  

在前端项目中引入 Git 进行版本管理，并配置 Unity 专用 .gitignore 文件，解决了以下问题：

四、WebSocket 接入过程中遇到的问题及解决方式  

问题一：WebSocket 类型无法识别  

在 Unity 编写 WebSocketManager 脚本时出现错误，提示无法识别 WebSocket 类型。  
经排查发现，Unity 原生并不提供跨平台 WebSocket 实现，需要额外引入第三方库。

解决方式：  
 对比 NativeWebSocket 与 WebSocketSharp 等方案  
 明确插件需完整导入源码而非单个文件  
 将正确的 WebSocket 源码文件放入 Unity 项目 Assets 目录后成功解决  

问题二：插件导入后无明显效果  

在导入 WebSocket 插件时，发现 Unity 未显示新增功能，且插件目录结构复杂。  
经分析确认，我错误地将部分仓库结构导入 Unity，而 Unity 实际只需要其 Assets 下的脚本文件。

解决方式：  
 仅保留插件中参与编译的 .cs 文件  
 将其整理放入 Unity 项目的Assets目录  
 重新编译后 WebSocket 类可正常使用  

五、前后端联调过程中遇到的主要问题回顾  

虽然本人主要负责前端，但在本地部署与联调过程中，需要协助后端进行优化以实现前后端通信。

1. Python 版本与依赖不兼容问题  

在安装后端依赖时，出现 uvicorn 等库无法安装的问题。  
原因在于本地 Python 版本为 3.9，而后端依赖及代码使用了 Python 3.10 以上版本特性。

解决方式：  
 明确后端 Python 版本要求  
 统一升级 Python 至 3.13  
 重新创建虚拟环境并安装依赖  

2. Windows 多 Python 环境切换混乱  

系统中同时存在 Python 3.9（Anaconda）与 Python 3.13，导致 python 与 py 命令指向不同版本。

解决方式：  
 使用 py 启动器确认可用 Python 版本  
 在项目目录中基于 Python 3.13 重新创建虚拟环境  
 后续所有操作均在虚拟环境激活后进行  

3. 虚拟环境与 PyCharm 解释器不一致  

在 PyCharm 中运行后端代码时出现找不到 fastapi 模块的错误。  
经排查发现，PyCharm 使用的是默认生成的虚拟环境，而非项目实际使用的 venv。

解决方式：  
 手动将 PyCharm Interpreter 切换至项目 venv  
 确保 IDE 与命令行使用同一 Python 环境  

4. 后端模型定义不一致导致 ImportError  

运行后端时出现 ImportError，提示无法从 models.py 中导入 Employee。  
经检查发现 main.py 中导入了 Employee，但 models.py 中并未定义该模型。

处理方式：  
 将问题定位为后端代码结构不一致  
 向后端同学反馈，要求补充模型或移除无效导入
